## TD-01 / TD-02 D1 기준선과 소유권

### 해결 내용

- `packages/db/drizzle-v2`에 7개 migration을 새로 구성했다.
- 기존 migration 파일을 재작성하지 않고 새 canonical chain으로 분리했다.
- 일반 table은 Drizzle schema, FTS virtual table/trigger는 reviewed SQL이 소유한다.
- OAuth runtime DDL을 제거했다.
- transfer allowlist는 23개 보존 대상 일반 table을 포함하고 2개 OAuth state/token table과 FTS를 제외한다.

### 남은 위험

현재 `wrangler.toml` binding은 기존 `nihongo-n3-prod`다. production ledger가 정상화된 것은 아니므로 prod-v2 전환 전에는 `완료`가 아니라 `구현 완료`다. 기존 DB에 migration 이력을 임의 backfill하지 않는다.

## TD-03 / TD-04 API 계약

### 해결 내용

- public 52 paths/56 operations, admin 7 paths/8 operations 생성
- `api.d.ts`, `admin-api.d.ts` 생성
- vocab/grammar/kanji façade를 `openapi-fetch` path/params 타입으로 전환
- runtime route = documented route + internal exceptions 테스트
- admin spec/docs를 admin session으로 보호
- homophone route는 검수 완료 전 public spec에서 숨김

### 남은 위험

legacy handler façade는 유지되므로 generic response schema가 일부 `unknown`이다. 기능별로 실제 DTO schema를 구체화해야 하지만, path/verb/parameter drift는 현재 CI에서 차단된다.

## TD-05 / TD-07 콘텐츠 계약

- shared JLPT level은 N5~N1을 표현할 수 있다.
- 운영 manifest는 실제 존재하는 N5~N3 13개 source만 사용한다.
- parser는 `의미`, `뜻`, `한국어 뜻`을 인식하고 빈 뜻을 실패시킨다.
- source별 row/checksum, category, required field, duplicate, FK, FTS parity를 검증한다.
- N2/N1 WIP는 별도 branch로 격리했다.

N2/N1 타입 확장을 콘텐츠 출시로 오인하지 않는다. 원본 7개와 provenance가 없으면 source mapping에 추가하지 않는다.

## TD-08 오디오

공개 Worker route의 요청 시 생성은 제거했다. 승인된 R2가 1순위이고 browser Japanese voice가 fallback이다. Google 전체 배치는 관리자 인증, `execute:true`, provider `google`, approval token을 요구한다.

청해 API가 `audio_r2_key IS NULL`인 문장에도 존재하지 않는 legacy 경로를 조합하던 결함을 제거했다. 이제 승인된 DB 키만 응답하며 fresh DB에서는 브라우저 fallback을 사용한다. 오디오 요소도 사용자 재생 전에는 서버 파일을 preload하지 않아 미생성 R2로 인한 페이지 로드 404를 만들지 않는다.

남은 4,954건은 `verify:fresh`에서는 warning이고 `verify:fresh:audio` 재검증에서는 유일한 blocking failure였다. 이를 숨기기 위해 verifier 최소값을 낮추지 않는다.

## TD-09 테스트 종료

## TD-12 LearningTrack

계정의 track, OAuth state, React Query key, IndexedDB user ID, self-check/character localStorage를 user×track으로 분리했다. Chromium과 WebKit E2E에서 TOPIK과 JLPT 카드가 다른 namespace에 유지됨을 검증했다.

TOPIK은 foundation-only이므로 실제 문제·채점·추천이 구현됐다는 의미가 아니다.

## TD-13 / TD-14 운영 증명

Workers는 PII 없는 JSON request log와 observability sampling을 설정했다. Logpush/R2 보존과 5xx 1%/5분, auth failure trend, D1 error alert는 Cloudflare 운영 설정이 필요하다.

Backup은 FTS를 제외한 일반 table을 table별 export하고 manifest SHA-256, allowlist, row count, FK, 재구축한 FTS parity를 fresh D1 restore drill에서 확인한 뒤 R2에 업로드한다. GitHub billing 해제 후 실제 Backup workflow 성공이 완료 조건이다.
